# Reglas del Proyecto (app-diagnostico-financiero-local)

Estas son las directrices y reglas estrictas del proyecto. Deben cumplirse en todo momento durante el ciclo de desarrollo y la interacción con el agente.

### 1. Metodología de Desarrollo (TDD Estricto)
- **TDD Estricto (RED ➔ GREEN ➔ REFACTOR)**:
  - **Regla**: SIEMPRE escribir o actualizar las pruebas primero (fase RED) y verificar que fallen por la razón esperada ANTES de modificar el código de producción (fase GREEN).
  - Aplica tanto en el Backend (Rust: `cargo test`) como en el Frontend (React/TS: `pnpm test`).
  - Sin excepciones ni "cowboy coding" (modificar código directamente sin test RED previo).

### 2. Flujo de Git y Pull Requests
- **Commits Manuales**:
  - **Regla**: El usuario realiza los `git commit` y `git push` manualmente desde su terminal. El agente nunca ejecuta commits ni pushes automáticos.
  - Formato Conventional Commits (ej. `feat(export): ...`). NUNCA agregar atribuciones de IA ni Co-Authored-By.
- **PRs Apilados al Tracker (Chained PRs)**:
  - **Regla**: Todas las ramas hijas de una funcionalidad deben abrir su PR teniendo como base la rama tracker correspondiente (ej: `--base feat/mvp-v2.1-gap-analysis`). NUNCA apuntar directamente a `main` desde ramas hijas.
- **Creación del PR del Tracker**:
  - **Regla**: El PR de la rama tracker (hacia `main` o su rama padre) se crea después de mergear la primera rama hija en ella, evitando PRs en borrador vacíos.
- **Límite de Cambios por PR**:
  - Budget de máximo ~400 líneas cambiadas por PR para mantener revisiones enfocadas y manejables.
- **Prevención de rama**: NUNCA se inicia código en `main`. Siempre se debe hacer `git checkout -b feat/<nombre-cambio>` antes de implementar un change SDD.

### 3. Especificaciones y Registro de Memorias (OpenSpec & Engram)
- **Idioma de Artefactos**:
  - OpenSpec (Especificación y Diseño): Redactado en Español neutral LATAM.
  - Engram (Memorias del agente): Guardado en Inglés.
- **Spec Canónico**:
  - La fuente única de verdad para las especificaciones es la ruta estructurada (ej: `openspec/changes/<feature>/specs/<feature>/spec.md`). El archivo plano `spec.md` en la raíz del cambio actúa solo como puntero.
- **Identificador Único en Engram**:
  - El nombre del proyecto en Engram DEBE ser siempre `app-diagnostico-financiero-local` en cualquier plataforma o agente.

### 4. Arquitectura y Código (Frontend & Backend)
- **Aislamiento IPC (Tauri ➔ React)**:
  - Toda la comunicación entre React y Rust debe pasar por los wrappers tipados en `src/data/tauri-commands.ts`. Prohibido llamar a `invoke()` directo desde componentes UI.
- **Cálculos de Dominio Puros**:
  - Toda la lógica financiera y matemática vive en `src/domain/` mediante funciones puras (sin acoplamiento a React ni a Tauri).
- **Estructura UI**:
  - Sin React Router; la orquestación de paneles/organismos se gestiona directamente en `src/App.tsx`.
